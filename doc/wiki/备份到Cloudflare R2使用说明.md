# 备份到 Cloudflare R2 使用说明

DevSidecar（v2.2.10+）的 WebUI 内置**备份功能**：把整台机器的 `~/.dev-sidecar` 配置目录打包加密后上传到 S3 兼容对象存储，用于配置损坏、误删、换机迁移时一键恢复。本教程以 **Cloudflare R2**（免费额度大、国内可直连、无出口流量费）为例，同样适用于 AWS S3 / MinIO / 阿里云 OSS 等 S3 兼容存储。

**备份内容**：`config.json`（用户配置）、远程配置缓存（`remote_config*.json5`）、**CA 证书与私钥**（恢复到新机后所有设备无需重装证书）、`setting.json`、域名白名单等整个配置目录；自动排除 `logs/`、`xray/` 运行态、`running.json` 与备份设置本身。

---

## 1. 准备 Cloudflare R2

1. 打开 [Cloudflare 控制台](https://dash.cloudflare.com)，左侧菜单 **存储和数据库 → R2 对象存储**（首次进入按提示开通即可，免费额度无需绑卡验证的情况以页面提示为准）。
2. R2 免费额度：每月 **10 GB 存储 + 100 万次 A 类操作（写入/删除）+ 1000 万次 B 类操作（读取/列表）**。dev-sidecar 每次备份约 70 KB、每天一次，连 1% 额度都用不到。

---

## 2. 创建存储桶

1. R2 **概述**页右上角点 **创建存储桶**。
2. **存储桶名称**：例如 `dev-sidecar`（全局唯一，仅小写字母、数字、连字符；名称创建后不可改）。
3. **位置**：保持「自动」即可（对中国大陆用户会自动落在亚太地区）；**默认存储类**：标准。
4. 点 **创建存储桶**。

> 备份对象会按 `dev-sidecar/<你的主机名>/<时间戳>.tar.gz(.enc)` 的键名存放。多台机器共用同一个桶时按主机名自动隔离、互不覆盖。

---

## 3. 创建 API 令牌（最小权限）

1. R2 概述页右侧 **管理 API 令牌** → **创建 Account API 令牌**（备份属于长期生产用途，推荐 Account 令牌：即使帐户成员变动也不会失效）。
2. **令牌名称**：`dev-sidecar-backup`。
3. **权限**：选 **对象读和写**——只允许读写指定桶里的对象。**不要**选「管理员读和写」（那是管整个 R2 的大权限）。
4. **指定存储桶**：选 **仅应用于特定存储桶** → 勾选刚创建的 `dev-sidecar`。
5. **TTL**：永久；**客户端 IP 筛选**留空（家庭宽带 IP 经常变化）。
6. 点 **创建 Account API 令牌**，页面会显示三样**只显示一次**的凭据，立即抄存：

   | 凭据 | 用途 |
   |---|---|
   | 访问密钥 ID（Access Key ID） | WebUI 的 AccessKeyId |
   | 机密访问密钥（Secret Access Key） | WebUI 的 SecretAccessKey |
   | S3 API 终结点（形如 `https://<account_id>.r2.cloudflarestorage.com`） | WebUI 的 Endpoint |

> ⚠️ 关掉该页面后这些值**不会再显示**。忘记保存只能删除令牌重建。R2 概述页的「帐户详情」卡随时可再查 S3 API 终结点，但密钥对不行。

---

## 4. 在 WebUI 填写备份设置

打开 WebUI（默认 `http://127.0.0.1:31182`）→ 左侧 **☁️ 备份**：

| 字段 | 填什么 |
|---|---|
| Endpoint | `https://<account_id>.r2.cloudflarestorage.com`（上一步的 S3 API 终结点） |
| Region | `auto`（Cloudflare R2 固定填 auto） |
| Bucket | `dev-sidecar` |
| AccessKeyId / SecretAccessKey | 上一步抄存的两把密钥 |
| 对象前缀 | 默认 `dev-sidecar/`（对象按 `<前缀>/<主机名>/` 隔离） |
| 加密口令 | **强烈建议设置**：备份含 CA 私钥，设置后归档以 AES-256-GCM 加密再上云 |
| 保留份数 | 默认 7：每台主机最多保留 7 份，超出自动删除最旧的；0 = 不清理 |
| 定时备份 | 启用后每 24 小时自动备份一次（间隔可改） |

操作顺序：**测试连接** → 看到「连接成功：bucket 可访问」→ **保存设置** → **立即备份** 做一次真实验证。成功后「云端备份列表」出现带 🔒 标记的 `.tar.gz.enc` 条目，Cloudflare 桶页也能看到该对象。

---

## 5. 日常使用

- **立即备份**：手动打包上传一次。
- **云端备份列表**：每份备份可 **恢复**（覆盖回本机）、**下载**（导出 `.enc` 归档文件）、**删除**（不可恢复，有二次确认）。
- **定时备份**：服务内每 10 分钟检查一次是否到达设定间隔，到达才执行。改设置即时生效，无需重启服务。
- 失败信息会记录在「备份操作」卡的状态区（如凭据失效、网络超时），修好后下一次备份/定时检查会自动继续。

---

## 6. 恢复（含新机器灾备）

**本机恢复**：备份列表 → **恢复** → 确认弹框 → 服务自动把当前 `config.json` 留一份 `config.json.bak-restore-<时间>` 本地副本 → 解包覆盖配置目录 → 按提示**重启服务**生效（弹框可直接触发重启）。

**新机器恢复**（原机报废/迁移）：

1. 新机安装 dev-sidecar 并打开 WebUI 备份页。
2. 填写与原机相同的 Bucket、对象前缀、AccessKeyId / SecretAccessKey、**同一加密口令**（Endpoint 相同——同属一个 Cloudflare 帐户）。
3. 刷新列表即可看到原机主机名下的所有备份，选择任意一份恢复、重启。
4. CA 证书与私钥随备份回来，各设备的信任**无需重装**。

---

## 7. 重要注意事项

- **加密口令只存在本机** `~/.dev-sidecar/backup.json`，不随备份上传。口令一旦丢失，已加密的备份**永久无法恢复**——请把口令抄记到密码管理器。
- **更换口令只影响之后的新备份**；恢复旧备份时需要用备份当时设置的口令。
- 备份设置（含密钥、口令）独立于主配置树，不出现在配置页的 JSON 视图里，也不会被打进备份本体；WebUI 显示掩码 `******`，保存时留空即保留旧值。
- **凭据泄露怎么办**：令牌只授权这一个桶、且只有对象读写权限，影响面可控。怀疑泄露时到 Cloudflare「管理 API 令牌」删除该令牌重建，再到 WebUI 备份页填新密钥对即可。
- R2 计费可放心：备份场景远低于免费额度；不放心可在控制台「账单仪表板 → 添加预算警报」。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 测试连接报 `BACKUP_NOT_CONFIGURED` | Endpoint / Bucket / AccessKeyId / SecretAccessKey 没填全 |
| 备份/列表报 502、消息含 `SignatureDoesNotMatch` 或 `AccessDenied` | 密钥对不匹配、令牌被删或选错了存储桶范围；到 Cloudflare 核对令牌 |
| 恢复报「该备份已加密，请先在备份设置中填写加密口令」 | 本机 `backup.json` 没有口令（新机场景先填口令再恢复） |
| 恢复报「解密失败：加密口令不正确」 | 当前口令与该份备份加密时的口令不一致 |
| 换了桶或前缀后列表空了 | 列表只显示当前桶/前缀下的对象；旧桶里的备份仍在 Cloudflare，改回原桶/前缀即可继续访问 |

API 层面的备份端点契约见 `doc/webui-api.md`（`/api/backup/*`，可用于脚本化调用）。
